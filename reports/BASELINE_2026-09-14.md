## Pipeline read from source

The current path is:

`CaptureTargetSelector` → `CaptureManager` (GDI+/Desktop Duplication/WGC) → reusable RGB planar tensor → `OnnxModelSessionFactory`/`TensorRTEngine` → `ModelOutputAdapter` canonical `[1,N,6]` output → `PredictionFilter` → `StickyAimSelector` → aim-point offsets → prediction → `MouseManager`.

- Model output is normalized into capture-local physical pixels.
- `Prediction.ScreenCenterX/Y` adds the capture origin exactly once and supports negative desktop coordinates.
- WGC supplies a monotonically increasing frame number plus `Stopwatch` receipt timestamp; duplicate WGC frames are rejected before movement.
- Sticky Aim already associates by class/head-body relationship, IoU, distance, size, confidence and hysteresis, but had no durable `TargetTrackId`.
- The old class named `KalmanPrediction` used only diagonal covariance, sampled `DateTime.UtcNow` instead of the frame timestamp, and was not reset from a target identity change.

## Confirmed source defects

1. Six public legacy control factories in `MainWindow.xaml.cs` always threw `NotImplementedException`. No call site remained; current UI creation uses the two local `SectionBuilder` implementations.
2. Recognition scan orchestration used two non-event `async void` methods, preventing callers from observing their lifetime.
3. WGC resize cleanup explicitly disposed frames already owned by `using`, creating a double-dispose path.
4. DirectX display-change reinitialization swallowed every exception.
5. Prediction state did not have a stable target identity and could retain velocity after a person/model/capture-context change.
6. Sticky Aim retained the previous WGC session's last frame ID after capture generation changed, so a recreated session whose counter restarted at 1 could reject valid new frames.
